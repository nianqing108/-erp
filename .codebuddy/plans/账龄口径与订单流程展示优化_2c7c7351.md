## 需求概述

针对用户实际使用中发现的 4 个问题进行修正：

1. **账龄口径修正**：用户填写了「约定到期」为 30 天后，仪表盘账龄仍显示在 0-30 天档。原因：当前账龄按**实际发货日**起算（事实账龄），与用户预期不符。需改为**按约定收款日起算的逾期账龄**（未填约定收款日时回退用发货日兜底），图表改名「逾期账龄分布」，四档文案改为「逾期 0-30 天 / 31-60 天 / 61-90 天 / 90 天以上」，并新增「未到期」档（约定收款日未到、或按发货日兜底尚未逾期的订单），保证各档合计仍等于应收欠款总额。
2. **字段改名**：「约定到期」改为通俗易懂的「**约定收款日**」（数据库字段 `due_date` 与接口参数名不动，仅改前端展示文案：新建订单、编辑订单、订单详情概要）。
3. **订单详情步骤条改为 4 步**：录入 → 待发货 → 待付款 → 已完成。同时 `draft` 状态中文名从「录入」改为「**待发货**」（列表状态标签、状态筛选下拉、详情步骤条、后端错误提示文案保持一致），即录入动作完成后订单即处于「待发货」状态。
4. **付款结清后「已完成」不是绿色的修复**：根因是 `el-steps` 中 `active` 停在末步时末步渲染为蓝色“进行中”；需让 paid 状态时 `active` 越过末步索引，使全部步骤呈绿色完成态。同时将状态标签从 CSS 变量覆盖方式改为 `el-tag` 内置语义色（info/warning/primary/success/danger），确保「已完成」稳定显示绿色。

## 不变项

- 发货一步直达流程（draft → shipped → paid）、取消仅限未发货、应收欠款口径（仅 shipped 未结清）均维持不变

## 技术方案

### 后端（Spring Boot）

1. **账龄起算基准改造**（`DashboardService.bucketize`）：

- 基准日优先级：`dueDate`（约定收款日）> `shipmentDate`（发货日兜底）
- `days = ChronoUnit.DAYS.between(基准日, today)`；`days < 0` 归入「未到期」档，不参与逾期分档
- `AGING_BUCKETS` 常量改为 5 档：`未到期 / 逾期 0-30 天 / 逾期 31-60 天 / 逾期 61-90 天 / 逾期 90 天以上`

2. **数据链路补字段**：`DebtRowVO` 增加 `dueDate` 字段；`OrderMapper.xml` 的 `selectShippedDebtRows` SELECT 补充 `o.due_date AS dueDate`
3. **状态文案**：`OrderStatus.DRAFT` 的 label 从「录入」改为「待发货」，相关业务异常提示文案同步（如“仅「待发货」状态订单可发货”）

### 前端（Vue3）

1. **状态标签语义色**：`format.ts` 的 `STATUS_META` 增加 `type` 字段（待发货=info、待付款=primary、已完成=success、已取消=danger、待出货(历史)=warning），全部 `el-tag :class` 用法改为 `:type`；删除 `style.css` 中 `st-*` 覆盖类
2. **改名**：`OrderList.vue`（新建对话框）、`OrderDetailDrawer.vue`（概要 kv 与编辑对话框）中「约定到期」→「约定收款日」
3. **步骤条修复**（`OrderDetailDrawer.vue`）：

- 步骤改为 4 步：录入 → 待发货 → 待付款 → 已完成
- `stepActive` 映射：draft/pending=1、shipped=2、paid=**4**（越过末步索引使全部变绿）、cancelled=1（process-status=error 红叉）

4. **仪表盘**（`Dashboard.vue`）：卡片「在录金额」→「未发货金额」；账龄环形图标题改「逾期账龄分布」，配色调整为 5 档（未到期=灰蓝，逾期档由橙到红递进）

### 性能与兼容

- 账龄仍为一次 SQL 取数 + Java 侧分档，无额外查询开销；分档仅新增一个常量桶与一个判断分支，O(n) 不变
- `due_date` 数据库字段与接口入参名不变，旧数据无需迁移；未填约定收款日的订单自动回退发货日口径，行为不劣于现状
