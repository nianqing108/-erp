# 01 项目章程与里程碑

## 1.1 项目背景

中小企业（供货商）大多依靠 Excel 开展订单业务管理，随着业务量增长暴露出四类痛点：

1. **数据分散**：订单、出货、收款信息散落在多份表格，无法串联追溯
2. **欠款统计繁琐易错**：客户分批付款后欠款余额靠手工计算，极易出错
3. **状态难以追踪**：订单处于「已发货 / 已收款 / 未收款」哪个阶段只能靠口头确认
4. **对账成本高**：月底给客户出对账单需要从多张表人工拼凑

本项目以最小化成本交付一套**轻量、低成本、上手快**的订单 ERP 工具，打通「客户 → 订单 → 出货 → 收款 → 欠款 → 报表」业务闭环。

## 1.2 项目目标

| 编号 | 目标 | 度量方式 |
| ---- | ---- | ---- |
| G1 | 实现订单全生命周期管理 | 录入 → 待出货 → 待付款 → 已完成 完整流转可顺畅执行 |
| G2 | 提供实时欠款统计 | 系统总欠款、单客户欠款查询结果与手工台账逐笔核对一致 |
| G3 | 自动生成月度经营报表 | 月度订单量、出货量、回款额、完成率与底层明细完全匹配 |
| G4 | 独立管理已取消订单 | 取消订单不参与任何欠款档位核算 |
| G5 | 替代 Excel 手工台账 | 业务日常操作全部在系统内完成，无需再维护线下台账 |

## 1.3 项目范围

**本期包含**：客户管理、订单管理、出货管理、收款管理、欠款统计、月度经营报表、订单状态流转、客户对账单。

**本期明确排除**：库存管理、采购管理、用户权限管理、多仓库、审批流、消息通知、工资财务记账。

> 权限说明：文档排除权限体系，但公网裸奔风险不可接受，采用**零代码方案** —— Nginx `auth_basic` 一层 HTTP Basic 访问控制，仅在部署配置层实现，不侵入业务代码。

**本期仅建表不开发**：`order_items`（订单明细）作为扩展预留，不开发业务页面。

## 1.4 团队与职责分工

本项目为 **1 人全栈** 编制，一人承担全部角色。为避免角色混淆导致质量缺口，明确划分「角色帽子」并在各阶段切换：

| 角色 | 职责 | 主要产出 |
| ---- | ---- | ---- |
| 产品经理 | 需求梳理、优先级排序、验收标准定义 | `docs/02`、`docs/08` |
| 架构师 | 技术选型、架构与数据库设计、接口契约 | `docs/03`、`docs/04` |
| 后端开发 | Spring Boot 业务实现、单元测试 | `backend/` |
| 前端开发 | Vue3 页面实现、交互与可视化 | `frontend/` |
| 测试工程师 | 用例设计、集成测试、UI 冒烟 | `docs/06`、`backend/src/test` |
| 运维工程师 | Docker 部署、备份恢复、监控告警 | `docs/07`、`docker-compose.yml` |

> 单人开发的**质量补偿机制**：由于无交叉评审，必须依靠 ① 强制单元测试覆盖率门禁 ② 每个迭代末的自检清单（见 `docs/06`）③ 上线前完整回归一遍 6 条验收标准 来兜底。

## 1.5 关键业务决策（已与业务方确认）

| 决策项 | 结论 | 理由 |
| ---- | ---- | ---- |
| 欠款统计口径 | **仅 `shipped` 状态计入应收欠款** | 未出货不形成应收，最贴合财务常识；`draft`/`pending` 另设「在录金额」「待发货金额」档位展示，避免信息丢失 |
| 订单编号 | 内部单号 `ORD+yyyyMMdd+4位流水` 自动生成不可手改；**新增客户订单号（PO 号）选填字段** | 供货商场景中部分客户会自带订单号，需保留用于对账与检索 |
| 账龄起算基准 | 实际发货日 `shipment_date` | 与欠款口径一致，未发货不产生账龄 |
| 超收款 | 严格禁止，累计收款不可超过订单总额 | 规避资金账目异常 |
| 工期 | 由原 4 周放宽至 **8 周** | 单人全栈承担前后端 + 运维 |

## 1.7 风险登记册

| 风险 | 概率 | 影响 | 应对措施 | 责任人 |
| ---- | ---- | ---- | ---- | ---- |
| 订单状态流转逻辑出错 | 中 | 高 | 状态可用动作收敛到 `OrderStatus` 枚举方法；单测覆盖全分支；DB enum 约束兜底 | 后端 |
| 欠款统计计算不准 | 中 | 高 | 修正多笔收款导致的 SUM 放大缺陷；核心 SQL 单测 + 手工台账比对 | 后端 |
| 单人开发无交叉评审 | 高 | 中 | 迭代末自检清单；强制单测覆盖率 > 70%；上线前完整回归 | 全角色 |
| 工期超期 | 中 | 中 | 优先保 P0（FR-01~04、06、07、12）；P1 统计报表可延后一周 | 全角色 |
| 生产数据丢失 | 低 | 高 | 每日 `mysqldump` 全量备份保留 30 天；数据卷持久化 | 运维 |
| 并发超收款 | 低 | 中 | 业务层累计校验 + 事务；订单号序列表 UPSERT 原子自增 | 后端 |
| 时区导致日期错乱 | 低 | 中 | 数据库、JVM、Docker、Nginx 统一 `Asia/Shanghai` | 运维 |
| 公网无鉴权被扫描 | 中 | 高 | Nginx `auth_basic` + 强密码；仅开放必要端口 | 运维 |
