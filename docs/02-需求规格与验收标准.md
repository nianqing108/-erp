## 2.2 业务规则明细

### 2.2.1 订单状态机

```
                    ┌──────────────┐
                    │  录入 draft   │
                    └──────┬───────┘
                           │ 确认发货 POST /{id}/ship
                           │ （实际发货日 + 物流单号选填）
            ┌──────────────┼──────────────┐
          取消              ▼              
            │       ┌──────────────┐        
            └──────▶│ 待付款 shipped │───────┐
                    └──────┬───────┘       │
                           │ 录入收款       │ 不可取消
                           │ （累计 ≥ 总额） │
                           ▼               │
                    ┌──────────────┐       │
                    │  已完成 paid  │◀──────┘
                    └──────────────┘
```

| 动作 | 前置状态 | 目标状态 | 约束 |
| ---- | ---- | ---- | ---- |
| 确认发货 | draft | shipped | 需填写实际发货日（不可早于下单日）；物流单号选填；发货即形成应收 |
| 录入收款 | shipped | shipped / paid | 累计收款 = 总额时转 paid；不可超收 |
| 取消订单 | draft | cancelled | shipped / paid / cancelled 拒绝取消 |
| 编辑订单 | draft | draft | 非 draft 状态禁止修改金额等核心字段 |

### 2.2.2 欠款口径

| 档位 | 计算口径 | 是否计入应收欠款 |
| ---- | ---- | ---- |
| 在录金额 | `status='draft'` 的 `SUM(total_amount)` | 否 |
| **应收欠款** | `status='shipped'` 的 `SUM(total_amount) − SUM(payments.amount)` | **是（唯一）** |
| 已结清 | `status='paid'` | 否（欠款为 0） |
| 已取消 | `status='cancelled'` | 否（完全排除） |

> **缺陷修正**：规划文档原 SQL 使用 `SUM(o.total_amount) - COALESCE(SUM(p.amount),0)` 且 `LEFT JOIN payments`，当一笔订单有多笔收款时，`total_amount` 会被收款行数放大 N 倍，导致欠款虚高。本期实现必须先按订单聚合收款再相减。

### 2.2.3 逾期账龄分布

- **起算基准**：约定收款日 `orders.due_date`（优先）；未填约定收款日的订单回退用实际发货日 `shipments.shipment_date` 兜底
- **统计对象**：`status='shipped'` 且未结清订单的未结余额（`总额 − 已收`）
- **分档**：未到期（约定收款日未到）/ 逾期 0-30 天 / 逾期 31-60 天 / 逾期 61-90 天 / 逾期 90 天以上；各档合计恒等于应收欠款总额

### 2.2.4 订单编号

| 字段 | 规则 | 可编辑 |
| ---- | ---- | ---- |
| `order_no` 内部订单号 | `ORD + yyyyMMdd + 4位流水`，如 `ORD202609040001`，按日重置 | 否 |
| `customer_order_no` 客户订单号 | 客户提供的 PO 号，选填，最长 64 字符 | 是 |

- 不做全局唯一约束，同一客户下重复时前端给出**软提示**但不阻断录入（不同客户可能给出相同 PO 编号）

### 2.2.5 月度报表指标定义

| 指标 | 定义 |
| ---- | ---- |
| 月度订单量 | 按下单日期 `order_date` 归属月份的订单笔数（不含已取消） |
| 月度出货量 | 按实际发货日 `shipment_date` 归属月份的出货笔数 |
| 月度回款金额 | 按到账日 `received_date` 归属月份的收款金额合计 |
| 订单完成率 | 该月下单且状态为 `paid` 的订单数 ÷ 该月下单订单总数（不含已取消） |

## 2.4 验收标准

验收采用「逐条核对 + 数据比对」方式，以下 6 条全部通过方可验收：

| # | 验收项 | 判定标准 | 对应需求 |
| ---- | ---- | ---- | ---- |
| A1 | **订单完整业务流程** | 录入 → 确认发货（一步直达）→ 录入收款 → 已完成，全流程可顺畅执行，无阻断 | FR-02/04/06/07 |
| A2 | **订单取消业务** | `draft` 可取消；`shipped`/`paid` 取消被拦截并给出明确提示；取消订单不计入任何欠款档位 | FR-05 |
| A3 | **欠款统计准确性** | 系统总欠款、客户欠款计算结果与手工台账逐笔核对一致 | FR-08/09 |
| A4 | **客户对账单** | 客户订单、出货、收款明细完整无遗漏，支持导出 Excel 且数据与页面一致 | FR-10 |
| A5 | **月度报表** | 统计数据与底层业务明细完全匹配，支持导出 | FR-11 |
| A6 | **异常拦截** | 非法状态操作给出明确提示，且数据库不产生脏数据（状态不变、无多余流水） | FR-04/NFR-03 |
