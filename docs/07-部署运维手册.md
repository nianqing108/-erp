# 07 部署运维手册（Linux + Docker 从零上线）

> **用什么数据库？**
> 正式部署使用 **MySQL 8.0**——它已打包进 Docker 编排，随应用一键启动，你**不需要**在服务器上单独安装 MySQL；
> 首次启动自动执行 `sql/init.sql` 建库建表，得到一个**空库**（不含任何演示数据）。
> H2 内存库仅用于本机没装 MySQL 时的快速演示，数据不持久，**不要**用于正式部署。

---

## 一、你需要准备

| 项 | 要求 |
| --- | --- |
| 服务器 | Linux（CentOS / Ubuntu / Debian 均可），建议 2 核 4G 起 |
| 已安装 | Docker 20+ 与 Docker Compose v2（没装看下面第二步） |
| 端口 | 80（前端访问）；8080 可选（后端接口/健康检查，不想暴露可不开放） |
| 软件 | 整个 `erp` 项目目录（git clone 或压缩包上传均可） |

## 二、安装 Docker（已装可跳过）

```bash
# 官方脚本一键安装（国内服务器如超时，可用阿里源镜像安装）
curl -fsSL https://get.docker.com | sh
systemctl enable --now docker

# 验证
docker -v
docker compose version
```

## 三、上传代码到服务器

```bash
# 方式 A：git（推荐，便于后续更新）
git clone <你的仓库地址> /opt/erp

# 方式 B：本机打包上传（在开发机上执行）
# tar --exclude=node_modules --exclude=.git -czf erp.tar.gz erp/
# scp erp.tar.gz root@服务器IP:/opt/ && cd /opt && tar xzf erp.tar.gz
```

## 四、配置并启动（核心三步）

```bash
cd /opt/erp

# 1. 配置密码（必须改！）
cp .env.example .env
vi .env
#   DB_PASSWORD=    改成强密码（数据库）
#   JWT_SECRET=     改成随机长字符串≥32位（登录令牌签名）
#   REGISTER_CODE=  设置一个注册邀请码（防止外人注册；留空=开放注册）

# 2. 一键构建并启动（首次会拉镜像+编译，约 5~10 分钟）
docker compose up -d --build

# 3. 查看状态与日志
docker compose ps
docker compose logs -f backend     # 看到 "Started ErpApplication" 即成功，Ctrl+C 退出
```

## 五、放行端口并访问

1. 云服务器控制台 → 安全组/防火墙 → 放行 **80 端口**（TCP）
2. 服务器本机防火墙：`firewall-cmd --permanent --add-port=80/tcp && firewall-cmd --reload`（CentOS）或 `ufw allow 80`（Ubuntu）
3. 浏览器打开 `http://服务器IP` → 注册页输入邀请码注册账号 → 登录 → 开始录入真实数据

> 内网/本机也可用 `http://服务器内网IP:8080/actuator/health` 验证后端，返回 `{"status":"UP"}` 即正常。

## 六、日常备份（强烈建议第一天就配）

```bash
# 手动备份一次试试（输出到 backup/ 目录）
bash -c 'mkdir -p /opt/erp/backup && docker exec erp-mysql sh -c "mysqldump -uroot -p\"\$MYSQL_ROOT_PASSWORD\" --single-transaction erp_db" > /opt/erp/backup/erp_$(date +%F).sql'

# 加入 crontab 每天凌晨 2 点自动备份（保留 30 天由脚本控制）
crontab -e
# 添加一行：
0 2 * * * docker exec erp-mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction erp_db' > /opt/erp/backup/erp_$(date +\%F).sql
```

## 七、后续更新发布

```bash
cd /opt/erp
git pull                                # 或上传新代码
# 数据库变更脚本均向后兼容（只加字段不删字段），无需手工改库
docker compose up -d --build backend frontend   # 只重建应用，MySQL 不动
docker compose logs -f backend                  # 确认启动成功
```

回滚：`docker compose down backend frontend && docker compose up -d`（镜像回退到上一版）；
数据还原：`docker exec -i erp-mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" erp_db' < backup/erp_日期.sql`。

## 八、常见问题

| 现象 | 处理 |
| --- | --- |
| 80 端口被占用 | `docker compose down` 后检查占用进程，或改 compose 中 frontend 端口映射（如 `8081:80`） |
| 改了 `.env` 不生效 | `docker compose up -d` 重建容器才会读取新环境变量 |
| 改了 JWT_SECRET 后全部要重新登录 | 正常现象：旧令牌全部失效，重新登录即可 |
| 忘记登录密码 | 直接换一个新用户名注册（有邀请码则用邀请码）；或删除对应用户后重注册 |
| 磁盘占用增长 | 主要是 MySQL 数据卷与日志；日志已限幅滚动，勿删 `mysql-data` 卷 |

## 九、数据在哪里（重要）

| 数据 | 位置 |
| --- | --- |
| 业务数据（客户/订单/收款/用户） | Docker 数据卷 `mysql-data`，随 `docker compose down` 保留；**`down -v` 会删卷，严禁随意执行** |
| 应用日志 | 容器内 json-file 限幅滚动（backend 20MB×5、frontend 10MB×3） |
| 数据库备份 | 宿主机 `/opt/erp/backup/` |
